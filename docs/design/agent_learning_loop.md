5기법(ORB · 모멘텀 · VWAP · 갭 · 양음봉)이 *동등 경쟁*(현재 가중치 30/25/25/20/20)한

## 1. 학습 신호 정의 — "기법이 잘했다"를 무엇으로 측정?

### 1-1. 1차 신호: 찬성 거래의 FIFO 성과 (이미 계측 존재)

소스: `app/analytics/strategy_performance.py`
- `_selected(episode)` → 해당 episode 에서 council 이 *채택한* 전략 목록(찬성).
- `episode_return(episode)` → FIFO 청산 기준 수익률(P-25 outcome).
- `_metrics_from_returns(returns)` → `win_rate` / `payoff_ratio`(평균이익÷평균손실) /
  `profit_factor` / `expectancy`(= win_rate·avg_win + (1−win_rate)·avg_loss).

**기법별 점수**: 그 기법이 *찬성했고 체결→청산된* 거래들의 묶음에 대해:

```
strategy_score(s) = expectancy(s)        # 1순위: 기대값(승률·손익비 결합)
보조지표         = win_rate(s), profit_factor(s), 찬성_거래수(s)
```

> expectancy 를 단일 학습 신호로 쓰는 이유: 승률만(고승률·저손익비 함정) 또는 손익비만
> (저승률 도박)으로는 왜곡됨. 기대값은 둘을 결합한 *거래당 평균 기대수익*.

### 1-2. 기여도 가중 (선택 — 2차 정교화)

한 거래를 여러 기법이 동시 찬성했을 때, 성과를 어떻게 배분하나?
- **MVP**: 찬성한 모든 기법에 *동일 귀속*(그 거래 수익률을 각 찬성 기법의 returns 에 1건씩 추가).
  단순·견고. 현재 `_strategy_block` 방식과 정합.
- **2차**: 그 거래에서 기법의 `weighted_score`(weight × score/100) 비중으로 *부분 귀속*.
  더 정밀하나 표본 더 필요 → 3단계 이후.

### 1-3. ★보류/기각 신호 포함 여부 — "안 산 게 옳았나"

T4b 계측(스캔 summary 영속화, 별도 승인 대기)이 쌓는 *보류(HOLD/skip)* 데이터를
**2차 학습 신호**로 활용 가능:
- 한 기법이 HOLD 한 종목이 *이후 하락* → 그 HOLD 는 "옳은 보류"(절약된 손실) → 소폭 가점.
- 한 기법이 HOLD 한 종목이 *이후 급등* → "놓친 기회"(기회비용) → 소폭 감점.

**설계 판단**: 보류 학습은 **3단계까지 보류**(scope-out). 이유:
1. 반사실(counterfactual) 수익률은 "샀다면" 가정이라 실현손익보다 **신뢰도 낮음**.
2. 보류 표본은 매수 표본보다 100× 많아(스캔마다 대부분 HOLD) **신호 희석/과적합 위험**.
3. 우선은 *실현된* 거래 성과로만 학습 — 단순·검증가능. 보류는 "기회손실 리포트"(advisory)로만 표시.

## 2. ★표본 충분성 게이트 (핵심 — 노이즈 학습 방지)

### 2-1. 기준

학습은 **기법별 최소 표본**을 모두 통과해야 *활성*. 그 전엔 **가중치 고정**(현재 정적값).

| 게이트 | 임계 | 근거 |
|---|---|---|
| 기법당 최소 청산 거래수 | **N_min = 30** | 비율 추정 표준오차가 ~0.09 이하로 떨어지는 실용 하한(이항 표준오차 √(p(1−p)/n), p=0.5, n=30 → ±0.09). 30 미만은 승률 ±15%p 이상 흔들림 → 노이즈. |
| 전체 학습 표본(5기법 합) | **150건** | 기법당 30 × 5. 라운드 단위 재학습 트리거. |
| 최소 관측 기간 | **10 거래일** | 단일 시장국면(상승장만/하락장만) 과적합 방지 — 여러 국면 포함. |
| 기법별 유효성 | 찬성 거래 ≥ N_min **AND** 청산 완료(outcome 라벨됨) | 미청산·미라벨 거래는 표본에서 제외. |

> 현재 청산 17건 → **게이트 미달**. 가중치 고정 유지가 *정상 동작*. 게이트는
> `INSUFFICIENT_SAMPLE` 상태를 반환하고 학습을 건너뛴다(조용한 실패 0 — 사유 로깅).

### 2-2. 신뢰구간 기반 보수화 (선택)

가중치 조정폭을 *표본 크기에 비례*시킨다: 표본이 적을수록(n→N_min) 조정폭→0,
표본이 많을수록(n≫N_min) 조정폭→상한. → "확신이 클 때만 크게 움직임".

```
adjust_scale = clamp((n − N_min) / (N_target − N_min), 0, 1)   # N_target=100
```

## 3. 가중치 조정 메커니즘

### 3-1. 현재 구조 (정적)

`agent_council.py`:
```python
STRATEGY_WEIGHTS: dict[str, int] = {
    "MOMENTUM": 30, "VWAP": 25, "ORB": 25, "GAP": 20, "CANDLE": 20,
}
```
집계 루프(`run_agent_council`)가 `STRATEGY_WEIGHTS.get(v.strategy)` 로 *매번 읽음*.

### 3-2. 동적화 설계 — **런타임 오버라이드 계층 재사용**(C1/T2 패턴)

새 인프라 0. 기존 `app/core/runtime_config.py` 의 effective-getter 패턴을 그대로 확장:

```
effective_strategy_weights() -> dict[str,int]
  = 런타임 오버라이드(strategy_weights) > 기본 STRATEGY_WEIGHTS
```

- **agent_council 변경은 단 1줄**: `STRATEGY_WEIGHTS.get(v.strategy)` →
  `effective_strategy_weights().get(v.strategy)` (집계 *규칙* 불변 — 값 소스만 동적).
  → **이것이 유일한 agent_council 판단부 접점. 구현 시 STOP·보고.**
- 학습 루프는 agent_council 을 *직접 수정하지 않고*, runtime_config 오버라이드 파일에만 쓴다
  (T2 와 동일 — 봇이 매 사이클 effective getter 로 읽어 반영, 재시작 불요).

### 3-3. 조정 공식 (점진적 — 급변 금지)

라운드(주 1회 또는 150건마다)마다:
```
rank 점수: z(s) = (expectancy(s) − mean_expectancy) / std_expectancy   # 기법 간 상대평가
제안 가중치: w'(s) = clamp( w(s) · (1 + α · z(s) · adjust_scale),  W_MIN, W_MAX )
정규화: 합을 기존 총합(=120)으로 스케일(상대 비중만 변동, 총량 보존)
```
- `α = 0.10` (라운드당 ±10% 한도 — 급변 금지).
- `W_MIN = 10, W_MAX = 40` (한 기법 몰빵·소멸 방지 클램프).
- **EMA 평활**: `w_new = 0.7·w_old + 0.3·w'` (한 라운드 충격 완화).

## 4. ★안전장치

| 장치 | 설계 |
|---|---|
| **몰빵 방지** | `W_MAX=40` 상한 + 총합 보존 정규화 → 한 기법이 전체를 못 먹음. 어떤 기법도 `W_MIN=10` 이하로 안 떨어짐(소수의견 보존). |
| **급변 방지** | 라운드당 ±10%(α) + EMA 0.3 + adjust_scale(표본 비례) → 한 번에 크게 안 움직임. |
| **운영자 승인 게이트** | 2·3단계: 학습이 *제안*만 생성 → 운영자가 "오늘 하루" 확인 후 적용(T2 와 동일 승인 UX). 자동 적용 전 **diff 표시**(전→후 가중치 + 근거 성적). |
| **롤백** | 모든 가중치 변경을 `strategy_weights_history` 에 append(타임스탬프·근거·표본수). 1클릭 "직전으로 되돌리기" + "기본값(정적 30/25/25/20/20) 리셋". |
| **ON/OFF 스위치** | `ENABLE_STRATEGY_LEARNING`(기본 false) + 런타임 `learning_enabled`. OFF 면 가중치 완전 고정. |
| **드리프트 감시** | 학습 적용 후 N거래의 성과가 적용 *전* 보다 나빠지면 자동 경고(+ 운영자에게 롤백 제안). |
| **감사 로그** | 모든 학습 결정(표본수·z점수·전후 가중치)을 advisory 로그로. is_order_signal=False. |
